# judge_lab – Implementierungsplan

> **Für agentische Ausführung:** REQUIRED SUB-SKILL: superpowers:executing-plans (oder superpowers:subagent-driven-development). Schritte nutzen Checkboxen (`- [ ]`).

**Ziel:** Hands-on-Infrastruktur „LLM-as-a-Judge mit Ground Truth“ (AP1–AP7 des Konzepts) lokal lauffähig und getestet, bereit für die Generalprobe in Colab.

**Architektur:** Python-Paket `judge_lab` (flaches Layout im Repo-Root) mit klar getrennten Modulen `snippets → prompts → llm → parsing → matching → scoring → scoreboard → runner → ui`. Daten (`snippets/`, `prompts/`) liegen als Dateien im Repo und werden über `config.REPO_ROOT` gefunden. Scoreboard ist eine Google-Apps-Script-Web-App; ihre Aggregationslogik ist eine reine Funktion und wird mit Node getestet.

**Tech Stack:** Python ≥ 3.10 (lokal 3.12 via `uv`), openai-SDK, pydantic v2, PyYAML, pandas, requests, ipywidgets, complexipy, pytest; Apps Script (V8) + Chart.js; Node 24 nur für Tests.

**Spec:** [docs/superpowers/specs/2026-10-31-judge-lab-design.md](../specs/2026-10-31-judge-lab-design.md)

## Global Constraints

- Dateinamen englisch; Kommentare, Docstrings und Doku deutsch; UI-Texte deutsch; Prompts an das LLM englisch.
- Keine Snippets oder Defekte generieren: Code nur aus QuixBugs-Commit `4257f44b0ff1181dedaedee6a447e133219fcebf` (byte-identisch) oder dem bestehenden `bank_account.py`.
- Ground Truth (`defects`, `SOLUTION.md`) gelangt nie in einen Prompt und vor der Auflösung nie in die UI.
- Abhängigkeiten nur: `openai`, `pydantic`, `pyyaml`, `ipywidgets`, `pandas`, `requests`, `complexipy`; dev: `pytest`.
- Konstanten exakt wie Spec 8.1: `TEMPERATURE = 0.0`, `MAX_TOKENS = 2000`, `CONCURRENCY = {"openrouter": 6, "ollama": 1}`, `CHALLENGE_MAX_SUBMISSIONS = 3`, `POINTS = {"tp": 2, "fp_bug": -1}`, `WEIGHTS = {"functional_correctness": .40, "reliability": .20, "maintainability": .25, "readability": .15}`.
- Timeouts: LLM 90 s (Ollama 180 s), Scoreboard 10 s mit 2 Retries; `findings_json` auf 5000 Zeichen gekürzt.
- Fehler in der UI als deutsche Meldung, Traceback nur im einklappbaren Debug-Bereich.
- Git: eigener Branch `feature/judge-lab`, kleine nachvollziehbare Commits, **kein Push**, keine Co-Author-Zeile.

## Review Focus

1. **Geschweifte Klammern** im Code (`shunting_yard`: `precedence = {…}`) und in JSON-Strings (`"suggested_fix": "d = {}"`): Template-Befüllung darf nicht `str.format` nutzen, `extract_json` muss String-Literale beim Klammerzählen beachten. → Tests in Task 6 und Task 7.
2. **Unsaubere Feldtypen vom LLM**: `"line_start": "7"`, `null`, Scores als `"8/10"` oder > 10, unbekannte Kategorie `"Bug"`/`"security"`. Erwartung: tolerant normalisieren statt Parse-Fehler. → Tests in Task 7.
3. **Teilausfall mitten in der Matrix**: ein LLM-Lauf wirft/timeoutet, Scoreboard nicht erreichbar. Erwartung: Matrix läuft weiter, Lauf als `parse_ok=False` mit `error` markiert, Records landen in CSV. → Tests in Task 11 und Task 12.
4. **Zelle doppelt ausgeführt** (Setup, Ollama, Einreichen): kein Doppelstart von `ollama serve`, Einreichungszähler zählt weiter statt neu. → Tests in Task 14 und Task 15.
5. **Fehlender API-Key / Platzhalter-Modell-ID**: deutsche Meldung vor dem ersten Lauf, kein Traceback. → Tests in Task 10 und Task 15.

### Task 8: `matching.py`

**Files:** Create `judge_lab/matching.py`, `tests/test_matching.py`

**Interfaces – Produces:**
```python
@dataclass(frozen=True)
class MatchResult: tp: int; fp: int; neutral: int; n_defects: int
    found_defect_ids: tuple[str, ...]; assignments: dict[int, str]   # Finding-Index → Defekt-ID
    recall: float | None; precision: float | None
```

Algorithmus (Spec 8.6): Kandidatenpaare (i, d) mit Überschneidung zu `d.accept_lines`; sortieren nach `(0 if overlaps(d.lines) else 1, gap(finding, d.lines), i, d.id)`; greedy zuordnen.
